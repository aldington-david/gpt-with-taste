# 已批准方案的实现对应

用户批准方案Ⅰ及 01–12，A–E 按原评估边界保留。修改放在独立分支，不安装、不自动信任、不合入默认分支。

| 项目 | 实现 | 边界 |
|---|---|---|
| 01 Skill 发现读取 | 官方 Using skills 全节 | 区分文件、环境、编排器资源；只有当前工具存在才适用 |
| 02 App/MCP/插件 | 官方 Apps、Plugins | 恢复发现、延迟加载和间接调用，不增加权限 |
| 03 工具与并行 | 官方 Rules for getting work done | 独立调用并行，有依赖的操作按顺序，实际 schema 决定参数 |
| 04 Shell 与文件 | 同上 | 转义、环境变量、多行正文等细则恢复 |
| 05 角色边界 | 原生角色保留，按 Main/Sub 分别组合 | 不复制原生角色消息，Sub 不接管全局验收 |
| 06 生命周期 | binding.md 衔接现有事件契约 | 消息、邮箱唤醒、任务完成及超时分开；不模拟未派发事件 |
| 07 授权拒绝 | Main/Independent 加入官方权限节 | 只读范围仍保留，Sub 由父任务和原生权限管理 |
| 08 追问压缩 | 官方 Working with the user | 处理新增要求、异步澄清及上下文续接，不虚构历史访问 |
| 09 进度交付 | 官方交互、格式、可视化片段 | 保留 Taste 人格，采用文件链接和科学绘图规则 |
| 10 提醒一致性 | 统一生成三份 compact Steer | 不每轮重复加载完整机制，旧段落改动需要审阅 |
| 11 hook 契约 | 核对原有 steer、local-tools、codex-plugin | 正确实现不重写；宿主信任与实际送达需实测 |
| 12 ChatGPT | 新增纯偏好 skill 构建目标 | 不加入 Codex API、MCP 或本地 hooks |

A：保留合理分工、避免重复劳动与独立审查，但主代理仍须整合验收。B：研究和反证处理按原任务范围保留。C：视觉改善服从既有设计与约定质量。D：保留相关验证，移除 Main/Sub 绝对禁止非必要哈希的段落，采用官方验证要求。E：保留 Taste 的语言、人格和内容取舍，没有重新合并 Humanizer。

`binding.md` 和 `steering.json` 是本 fork 的衔接与提醒文本，不是官方逐字原文。官方原文完整存档、所选章节、Taste 改前段落分别见 `official/`、`upstreams.json`、`patches.json`。原生角色/权限消息不在此重建。
